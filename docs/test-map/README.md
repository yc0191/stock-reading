# 테스트 지도

기능마다 어떤 테스트가 지키고 있는지, 어디가 비어 있는지를 한곳에 모은 지도입니다. 리팩터링·기능 추가·수정 때 그 기능을 지키는 테스트를 바로 찾아 돌리고, 테스트가 없는 곳을 커밋 전에 알아보기 위해 둡니다. 테스트 목록의 원본은 이 폴더입니다.

| 파일 | 범위 |
|---|---|
| [collector.md](collector.md) | `services/collector` |
| [market.md](market.md) | `services/market` |
| [news.md](news.md) | `services/news` |
| [notifier.md](notifier.md) | `services/notifier` |
| [briefing.md](briefing.md) | `services/briefing` |
| [scripts.md](scripts.md) | `scripts/` |

## 표의 칸

서비스 파일마다 표가 하나 있고, 한 행은 기능 하나입니다. 행은 대체로 Java 패키지 하나이며, 여러 기능이 섞인 큰 패키지는 나눕니다. 파일당 3~10행으로 둡니다.

| 칸 | 쓰는 것 |
|---|---|
| 기능 | 이 행이 지키는 기능을 쉬운 말로 |
| 대상 | 그 기능을 이루는 본 코드 이름을 `, `로 나열. Java는 최상위 타입 이름(class, interface, enum, record, @interface 모두), 파이썬·셸은 확장자를 붙인 파일 이름(`config.py`, `publish-tick.sh`). 설명은 쓰지 않습니다 |
| 단위 | 함수나 클래스 하나의 로직을 보는 테스트. 설정 바인딩·스프링 조립 확인, 이벤트 스키마(계약) 검사처럼 외부 의존을 부르지 않는 테스트도 여기에 씁니다 |
| 가상 | 외부 의존(외부 API, Kafka, DB, LLM, SMTP)을 가짜로 바꾸고 기능 흐름을 돌리는 테스트. 가짜 HTTP 서버, mock 처리한 포트·저장소·`KafkaTemplate`, 프로세스 안 테스트용 서버가 여기에 해당합니다 |
| 실제 | 실제 DB, 실제 서비스 흐름, 실제 외부 API를 쓰는 테스트 |

세 종류의 뜻은 `.claude/rules/commit.md`의 "테스트 3종"과 같습니다.

## 칸에 쓰는 값

단위·가상·실제 칸은 비워 두지 않고 아래 셋 중 하나로 채웁니다.

| 값 | 형식 | 언제 |
|---|---|---|
| 테스트 이름 | Java는 테스트 클래스 이름(`BrokerClientTest`), 파이썬은 테스트 파일 이름(`test_jobs.py`). 여러 개는 `, `로 나열 | 그 종류의 테스트가 있을 때 |
| `없음 - 이유` | `없음 - ` 뒤에 왜 없는지, 언제 채우는지 | 있어야 하지만 아직 없을 때 |
| `해당 없음 - 이유` | `해당 없음 - ` 뒤에 왜 필요 없는지 | 이 종류의 테스트가 뜻이 없을 때(예: 외부 의존이 없는 기능의 가상·실제) |

- 테스트와 `없음 - 이유`를 한 칸에 함께 쓸 때는 `; `로 나눕니다. 예: `InsightIntegrationTest [DB]; 없음 - 데일리 브리핑 작업에서 채움 [서비스 흐름]`
- 한 테스트가 여러 기능을 지키면 그 기능 행마다 적습니다.
- 적는 이름은 실제로 있는 테스트여야 합니다. 이름을 바꾸거나 지우면 지도도 함께 고칩니다.

## 실제 칸의 종류 표시

실제 칸에는 무엇을 실제로 확인하는지 테스트 이름(또는 `없음 - 이유`) 뒤 대괄호에 적습니다.

| 표시 | 뜻 |
|---|---|
| `[DB]` | 실제 Postgres(테스트 전용 데이터베이스)에 저장한 뒤 다시 읽어 확인 |
| `[서비스 흐름]` | 실제 Kafka로 서비스 여러 개를 잇는 흐름을 확인 |
| `[외부 API]` | 실제 외부 서버(시세, 공시, 뉴스 검색, 메일 등)를 호출해 응답을 확인 |

예: `FilingIntegrationTest [DB, 켜는 조건: NEWS_IT_DB_URL·NEWS_IT_DB_USER·NEWS_IT_DB_PASSWORD]`

## 환경변수로 켜는 테스트

평소 테스트 명령에서는 건너뛰고 환경변수가 있을 때만 도는 테스트는 대괄호 안에 `켜는 조건: `을 씁니다.

- 값이 정해진 경우: `켜는 조건: BROKER_PROBE=1`
- 값이 있기만 하면 되는 경우: 변수 이름만 `·`로 나열(`켜는 조건: MARKET_IT_DB_URL·MARKET_IT_DB_USER·MARKET_IT_DB_PASSWORD`)
- 여러 조건이 모두 필요하면 `, `로 함께 적습니다(`켜는 조건: BROKER_SMOKE=1, LIVE_PROBE_GUARD=1`).
- 전체 실행 스크립트의 옵션으로만 켜는 경우: `켜는 조건: test-all.sh --live`
- 가상 칸의 부하 측정처럼 실제 칸이 아닌 조건부 테스트도 같은 방식으로 적고 앞에 종류를 씁니다(`[부하, 켜는 조건: QUOTE_LOAD=1]`).

`켜는 조건`이 없는 테스트는 평소 테스트 명령에서 항상 돕니다.

## 테스트 도우미 줄

테스트를 돕기만 하고 스스로는 검증하지 않는 파일(스키마 읽기 도우미, 가짜 서버, 고정 시계 등)은 표 뒤 파일 끝에 한 줄로 적습니다.

```
테스트 도우미: ContractSchemas, FakeBrokerServer
```

도우미가 없어도 `테스트 도우미: 없음`으로 줄을 둡니다.

## 지도 검사

`scripts/check_test_map.py`가 지도와 저장소를 비교합니다. 설정 로더 테스트 명령으로 함께 돕니다.

```
services/briefing/.venv/bin/python -m pytest -c scripts/pytest.ini scripts/tests
```

검사만 따로 돌리려면 저장소 루트에서 `python3 scripts/check_test_map.py`를 실행합니다(문제가 없으면 종료 코드 0).

검사는 다음 네 경우에 실패합니다. 실패 메시지에는 고칠 지도 파일과 고칠 내용이 나옵니다.

1. 어느 행의 '대상' 칸에도 없는 본 코드 클래스·모듈이 있음
2. 단위·가상·실제 칸 중 테스트 이름도 `없음 - 이유`·`해당 없음 - 이유`도 없는 칸이 있음(빈 칸, 이유가 빈 `없음 -` 포함)
3. 지도에 적힌 테스트(또는 도우미)가 저장소에 없음
4. 어느 기능 칸에도, '테스트 도우미' 줄에도 연결되지 않은 테스트 파일이 있음

그 밖에 표 모양(칸 이름, 3~10행, 도우미 줄), 같은 대상이 두 번 적힌 경우, 코드에 없는 이름이 대상에 남은 경우도 함께 알립니다.

검사가 보는 범위는 다음과 같습니다.

| 지도 파일 | 본 코드 | 테스트 |
|---|---|---|
| `collector.md`, `market.md`, `news.md`, `notifier.md` | `services/<서비스>/src/main/java`의 최상위 타입 | `services/<서비스>/src/test/java`의 최상위 타입 |
| `briefing.md` | `services/briefing/src/briefing`의 `.py` | `services/briefing/tests`의 `.py` |
| `scripts.md` | `scripts/`의 `.py`, `.sh`(`scripts/tests` 제외) | `scripts/tests`의 `.py` |

## 지도를 고치는 방법

| 바꾼 것 | 지도에서 할 일 |
|---|---|
| 새 클래스·모듈 | 알맞은 기능 행의 '대상'에 이름을 넣습니다. 맞는 행이 없으면 새 기능 행을 만듭니다 |
| 새 기능 | 새 행을 만들고 단위·가상·실제 칸을 모두 채웁니다. 테스트가 아직 없으면 `없음 - 이유`를 씁니다 |
| 새 테스트 | 지키는 기능 행의 알맞은 칸에 이름을 넣고, 그 칸의 `없음 - 이유`가 더는 맞지 않으면 지웁니다. 도우미 파일이면 '테스트 도우미' 줄에 넣습니다 |
| 새 조건부 테스트, 건너뛰는 조건 변경 | 대괄호의 `켜는 조건`을 새로 쓰거나 고칩니다 |
| 테스트 삭제·이름 변경 | 적힌 칸에서 지우거나 바꿉니다. 칸이 비면 `없음 - 이유`를 씁니다 |
| 클래스·모듈 삭제·이름 변경 | '대상'에서 지우거나 바꿉니다. 행의 대상이 모두 사라지면 행을 지웁니다 |
| 행이 10개를 넘음 | 가까운 기능 행을 합치거나 기능 이름을 넓힙니다 |

실행할 때마다 바뀌는 테스트 개수는 지도에 적지 않습니다.
