# 가설 기록

"이렇게 하면 될 것이다"라는 믿음을 **검증 가능한 문장**으로 적고, 어떤 결과가 나오면 맞다고 볼지를 **데이터를 보기 전에** 고정해 두는 곳입니다. 설계 결정(ADR)과 달리 아직 사실이 아니며, 증명되면 기능 구현과 ADR의 근거가 됩니다. 특정 기능을 구현하거나 프로젝트를 진행할 때 증명해야 할 과제를 여기에 등록합니다.

증명된 결과는 루트 [README](../../README.md)의 "검증한 가설" 표에 나옵니다. 그 표는 이 폴더의 파일에서 **자동 생성**되며 직접 고치지 않습니다.

## 구성
```
H###-<이름>/
├── hypothesis.toml   # 정의: 주장, 판정 규칙, 검증 명령  ← 원본
├── hypothesis.md     # 배경, 용어, 위협 요인
└── results/          # 검증 실행 결과(집계만)            ← 원본
```
루트 README의 표는 위 원본에서 만든 사본입니다. 판정(증명됨 / 기각됨 / 판정 보류)은 사람이 적지 않고 판정 규칙에서 코드가 계산합니다.

## README 노출 규칙
| 가설 상태 | 루트 README |
|---|---|
| 판정 기준이 완성되지 않음 (`draft` 포함) | 노출하지 않음 |
| 기준 확정, 결과 없음 | "증명 진행 중"만 표시 |
| 기준 확정, 결과 있음 | 증명됨 / 기각됨 / 판정 보류와 근거(지표, 신뢰하한, 표본 수, 커밋, 재현 방법) |

판정 기준을 **결과를 얻은 뒤에 바꾸면** 이전 결과는 무효가 되어 다시 "증명 진행 중"으로 돌아갑니다(결과에 기준의 해시가 기록됨). 로컬 데이터가 필요한 가설은 근거에 "재현: 로컬 데이터 필요"로 표시됩니다.

## 사용법
```bash
python3 scripts/hypotheses.py verify H001      # 검증 명령 실행, 판정을 계산해 results/ 에 저장
python3 scripts/hypotheses.py render           # 루트 README 의 가설 표 갱신
python3 scripts/hypotheses.py render --check   # 표가 최신인지만 확인 (아니면 종료 코드 1)
```

### 새 가설 등록
1. `H###-<이름>/hypothesis.toml`을 만든다. 처음에는 `state = "draft"`로 두고 `id`, `title`, `claim`만 적어도 된다.
2. 판정 규칙(`[rule]`)과 검증 명령(`[verify]`)을 정하고 `state = "active"`로 바꾼다. **이 시점이 데이터를 보기 전이어야 한다.**
3. `verify`로 실행하고 `render`로 README를 갱신해 결과 파일과 함께 커밋한다.

### 판정 규칙의 종류
| kind | 쓰는 경우 | 판정 |
|---|---|---|
| `test` | 테스트로 확인할 수 있는 주장 | 검증 명령의 종료 코드가 0이면 증명됨, 아니면 기각됨 |
| `proportion` | 정확도처럼 비율로 확인하는 주장 | 명령이 JSON으로 출력한 집계(`n_total`, `n_answered`, `n_correct`)에서 정확 이항 신뢰하한과 커버리지로 계산 |

## 작성 원칙
- 판정 기준(통과 조건, 표본 수, 평가 지표)은 **결과를 보기 전에** 정하고, 바꿀 때는 이유와 시점을 기록합니다.
- 튜닝에 쓴 데이터와 최종 판정에 쓰는 데이터를 분리하고, 판정용 데이터는 한 번만 사용합니다.
- 시도한 구성(모델, 프롬프트)은 잘 나온 것만 남기지 않고 **전부** 보고합니다.
- 외부에서 수집한 데이터(기사 제목·요약, 종목)는 저장소에 올리지 않습니다. 각 가설 폴더의 `data/`는 `.gitignore`에 포함되어 로컬에만 둡니다. 결과 파일에는 집계만 저장합니다.
- 개인정보(보유 종목·수량·금액, 계좌)는 쓰지 않습니다.
- 확인하지 못한 사실은 "미확인"으로 표시합니다.
