# ADR-014: 발송기 안전 규칙 (실제 받은편지함을 보호한다)

- 상태: **확정** (구현·검증됨)
- 기록일: 2026-10-20

## 맥락
자동으로 반복되는 프로그램이 **실제 이메일 주소**로 메일을 보낸다. 지금은 데이터가 가짜(시뮬레이션)라서, 실수로 켜지거나 오류로 반복되면 받은편지함이 가짜 투자 정보로 채워지고 오해를 낳을 수 있다.

## 결정
| 규칙 | 내용 |
|---|---|
| 드라이런이 기본 | `notifier.send-enabled` 기본값 `false`. 설정이 없으면 로그만 남기고 아무것도 보내지 않는다. |
| 켰는데 설정이 비면 시작 실패 | 발송을 켰는데 발신·수신 주소나 SMTP 호스트가 비어 있으면 시작 단계에서 실패한다(조용히 아무것도 안 하지 않음). |
| 시간당 발송 한도 | 기본 6통(슬라이딩 1시간). 초과분은 보내지 않고 로그만 남긴다. 실패한 발송은 한도를 소모하지 않는다. |
| 제목 머리말 | 기본 `[시뮬레이션]`. 데이터가 가짜인 동안 진짜 투자 정보로 오해하지 않게 한다. |
| 중복 방지 | 같은 브리핑(같은 `eventId`)은 한 번만 발송한다. 발송이 실패하면 재시도하고, 성공한 뒤에만 기록한다. (메모리 기반이라 재시작 시 중복 가능) |
| 주소 마스킹 | 로그에는 주소를 마스킹(`a****@도메인`)해서만 출력한다. |
| 오류 메시지 redact | SMTP 서버의 오류 메시지에 주소·AWS 계정 번호가 들어 있으므로, **마스킹한 뒤에만** 던지고 원본 예외는 연결하지 않는다(원본이 로그에 찍히는 것을 막음). |
| 첫 구독은 `latest` | 소비자 그룹이 처음 생길 때 쌓인 과거 브리핑을 한꺼번에 보내지 않는다. |
| 비밀값은 `.env`(git 제외) | 받는 주소와 SMTP 자격증명은 코드·테스트·문서에 넣지 않는다. 테스트는 `example.com` 가짜 주소만 쓴다. |

## 검증
모든 규칙에 자동 테스트가 있고, 핵심 규칙은 **코드를 일부러 깨뜨려서 테스트가 실패하는 것까지 확인**했다(드라이런 기본값 제거, 한도 검사 제거, 기본값을 발송 켬으로 변경, 머리말 기본값을 깨진 글자로 변경, 오류 마스킹 제거).

## 실제로 겪은 함정
- **`.env`는 ASCII만:** 스프링이 `.env[.properties]`를 Latin-1로 읽어, `.env`에 넣은 한글 값(`[시뮬레이션]`)이 깨졌다. 한글 기본값은 UTF-8로 읽히는 `application.yml`에 둔다.

## 후속
한도 초과분이 버려지는 문제(요약 메일), 재시작 중복 방지(DB 기록).
