# ADR-013: 토픽은 사용하는 서비스가 선언하고, 브로커의 자동 생성은 끈다

- 상태: **확정** (구현·검증됨)
- 기록일: 2026-10-20

## 맥락
브로커의 토픽 자동 생성이 켜져 있으면, **소비자가 먼저 켜졌을 때 파티션 1개짜리 토픽이 만들어진다.** 이후 생산자가 같은 토픽을 3개로 늘려도, 이미 구독 중인 소비자는 기존 파티션만 읽는다. 실제로 시세처리기를 먼저 켰을 때 **3종목 중 1종목만 처리되고 나머지는 조용히 누락**되는 것을 재현했다(DB에 TEST01만 쌓임, 로그에 오류 없음).

## 결정
- 브로커 `KAFKA_AUTO_CREATE_TOPICS_ENABLE=false`
- **토픽을 생산하거나 소비하는 모든 서비스가 시작할 때 그 토픽을 선언**한다(이미 있으면 건드리지 않음). Java는 `NewTopic` 빈, Python은 `AdminClient.create_topics`.
- 같은 토픽의 파티션 수는 생산자와 소비자가 **동일**해야 한다.

## 결과
시작 순서와 무관하게 같은 결과가 된다. 소비자를 먼저 켜는 최악의 순서에서 파티션 3개가 모두 할당되고 모든 종목이 처리됨을 확인했다.

## 검증
- 각 서비스의 `TopicsConfigTest`: 선언한 토픽 이름과 파티션 수(3)를 검증하고, 빈 이름 충돌 같은 설정 오류가 스프링 컨텍스트 로딩 단계에서 드러나게 한다(실제로 `topics` 빈 이름 충돌 버그를 이 방식으로 잡음).
- 실제 실행: 소비자 우선 시작 순서로 종목별 DB 행이 모두 생성됨.

## 감수하는 점
파티션 수를 여러 서비스가 중복 선언한다. 값이 어긋나면 소비 누락이 다시 생길 수 있으므로, 변경 시 모든 선언을 함께 바꾼다(향후 한 곳에서 관리하는 방법을 검토).
