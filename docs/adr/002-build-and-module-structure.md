# ADR-002: Gradle Kotlin DSL 단일 멀티프로젝트, 공유 범위 제한

- 상태: **확정** (단, 이벤트 계약 공유 방식은 ADR-010 초안에 따라 변경)
- 기록일: 2026-10-20

## 맥락
서비스 여러 개와 공유 코드를 한 레포에서 관리한다. 서비스는 독립 배포 가능해야 한다.

## 고려한 대안
Maven, Gradle Groovy DSL, 서비스별 독립 Gradle 빌드

## 결정
- Gradle **Kotlin DSL**
- 루트 빌드 하나에 `services/*`를 서브프로젝트로 구성 (모노레포 1개)
- **버전 카탈로그**(`gradle/libs.versions.toml`)와 **컨벤션 플러그인**(`build-logic`)으로 공통 설정을 한 번만 정의

## 이유
1. 멀티모듈 빌드에 강하고 증분 빌드·캐시가 빨라 서비스가 늘어도 빌드 시간을 관리할 수 있다.
2. Kotlin DSL은 타입 안전해서 IDE 자동완성과 오류 검출이 좋다.
3. 서비스별 독립 빌드와 공유 라이브러리 배포는 이 규모에서 운영 부담이 이점보다 크다.
4. 서비스별 `bootJar`와 Docker 이미지는 따로 만들 수 있어 **독립 배포는 유지**된다.

## 공유 규칙 (분산 모놀리스 방지)
- 공유: 이벤트 계약(스키마 파일), 최소한의 공통 유틸
- 공유 금지: 도메인 로직, 엔티티, 서비스 간 직접 호출 코드
- 서비스마다 DTO를 직접 갖는다(예: `Envelope` 클래스는 서비스별로 별도 정의).

## 변경 이력
- Python 서비스가 Java 라이브러리를 쓸 수 없으므로, 계약은 "Java 공유 모듈"이 아니라 **언어 중립 스키마 파일(`contracts/`)** + 서비스별 읽기 코드로 바꿨다(ADR-010).

## 감수하는 점
같은 빌드에 묶여 한 서비스 변경이 전체 빌드에 영향을 줄 수 있다. CI에서 변경된 서비스만 빌드·배포하는 경로 필터로 완화한다(CI 도입 시).
