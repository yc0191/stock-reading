# ADR-002: Gradle Kotlin DSL 단일 멀티프로젝트, 공유 범위 제한

- 상태: **확정**
- 기록일: 2026-10-20

## 맥락
기준 3(대안이 둘 이상): 서비스 여러 개를 한 저장소에서 관리하면서도 서비스는 따로 배포할 수 있어야 한다.

## 고려한 대안
Maven, Gradle Groovy DSL, 서비스별 독립 Gradle 빌드

## 결정
- Gradle **Kotlin DSL**, 루트 빌드 하나에 Java 서비스를 서브프로젝트로 둔다(브리핑은 Python이라 따로).
- **버전 카탈로그**(`gradle/libs.versions.toml`)와 **컨벤션 플러그인**(`build-logic`)으로 공통 설정을 한 번만 정의한다.

## 이유
1. 멀티모듈 증분 빌드·캐시로 서비스가 늘어도 빌드 시간을 관리할 수 있다.
2. Kotlin DSL은 타입 안전해 IDE 자동완성과 오류 검출이 좋다.
3. 서비스별 독립 빌드와 공유 라이브러리 배포는 이 규모에서 운영 부담이 이점보다 크다.
4. 서비스별 `bootJar`와 이미지는 따로 만들어 **독립 배포는 유지**된다.

## 공유 규칙 (분산 모놀리스 방지)
- 공유: 이벤트 계약(언어 중립 스키마 파일 `contracts/`, ADR-010)
- 공유 금지: 도메인 로직, 엔티티, 서비스 간 직접 호출 코드. 서비스마다 DTO(`Envelope` 등)를 직접 갖는다.

## 감수하는 점
같은 빌드에 묶여 한 서비스 변경이 전체 빌드에 영향을 줄 수 있다.
