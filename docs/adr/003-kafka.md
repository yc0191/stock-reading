# ADR-003: 메시징은 Apache Kafka (KRaft, 셀프 호스팅, 단일 브로커)

- 상태: **확정**
- 기록일: 2026-10-20

## 맥락
기준 1(되돌리기 어려운 선택): 서비스 간 비동기 이벤트(시세, 뉴스, 브리핑, 알림)의 통로다. 트래픽은 관심 종목 수 수준이고 브리핑은 급변동 건별과 하루 2회 판이라 작다.

## 고려한 대안
RabbitMQ, Redis Streams, AWS Kinesis/SQS

## 결정
Apache Kafka. KRaft 모드, 셀프 호스팅, 클라이언트는 Spring for Apache Kafka(Java)와 confluent-kafka(Python).

## 이유
1. **리플레이:** 로직을 고친 뒤 과거 이벤트를 다시 흘려 결과를 재생성하고 평가해야 한다. 소비 후 사라지는 큐로는 어렵다.
2. **독립 팬아웃:** 같은 이벤트를 여러 서비스가 컨슈머 그룹으로 따로 소비한다.
3. **순서 보장:** 종목코드를 파티션 키로 써서 종목 안의 순서를 지킨다.
4. 파티션 설계, 컨슈머 lag, 재처리를 직접 운영해 보는 것이 이 프로젝트의 목표다.

## 감수하는 점
- 트래픽만 보면 Kafka가 꼭 필요하지는 않다. 위 이유 1~3이 근거다.
- 단일 브로커라 복제와 브로커 장애 복구는 없다.
- 관리형 대신 셀프 호스팅한다(비용).
- 토픽 이름과 파티션 수는 각 서비스의 `Topics`가 원본이고, 선언 규칙은 `CLAUDE.md`의 설계 규칙이다.
