# ADR-003: 메시징은 Apache Kafka (KRaft, 셀프 호스팅, 단일 브로커)

- 상태: **확정**
- 기록일: 2026-10-20

## 맥락
서비스 간 비동기 이벤트(시세, 뉴스, 브리핑, 알림)를 주고받는다. 프로젝트 목적은 Kafka 기반 MSA 경험이다. 실제 트래픽은 특정 종목, 브리핑 1시간 간격 수준으로 작다.

## 고려한 대안
RabbitMQ, Redis Streams, AWS Kinesis/SQS

## 결정
Apache Kafka. KRaft 모드, 셀프 호스팅, 클라이언트는 Spring for Apache Kafka(Java)와 confluent-kafka(Python).

## 이유
1. **리플레이:** 로직 개선·오류 수정 뒤 과거 이벤트를 다시 흘려 결과를 재생성하고 평가 세트를 만들어야 한다. 소비 후 사라지는 큐로는 어렵다.
2. **독립 팬아웃:** 같은 이벤트를 여러 서비스가 컨슈머 그룹으로 독립 소비한다.
3. **순서 보장:** 종목코드를 파티션 키로 써서 종목 내 순서를 보장한다.
4. **학습 목표:** 파티션 설계, 컨슈머 lag, 재처리, DLT 등 운영 경험.
5. 이벤트 기록이 보존되어야 **재시도하며 RAG 정확도를 개선**할 수 있다.

## 인지하고 있는 한계
- 실제 트래픽만으로는 Kafka가 필수가 아니다(오버엔지니어링 소지). 위 이유 1~5로 정당화한다.
- 서버 2대 구성이라 **단일 브로커**이며 복제·브로커 장애 복구(HA)는 시연할 수 없다.
- 관리형(MSK) 대신 셀프 호스팅하는 이유: 비용, 운영 경험이 목적.
