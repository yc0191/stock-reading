# ADR-019: 시세 응답 원문 저장과 조회 실패 기록 (market)

- 상태: **확정** (구현·검증됨. 원문 보존 기간은 아래 "미정")
- 기록일: 2026-10-27

## 맥락
수집기가 매초 응답 원문(`market.snapshot.raw`)과 조회 실패(`market.snapshot.failed`)를 내보내므로, 시세처리기(market)가 이를 전부 저장해야 나중에 변동 원인과 조회 실패를 분석할 수 있다. 하루치 행이 많아 날짜 단위로 지우거나 조회 범위를 좁힐 수 있어야 한다.

## 결정
1. **`price_snapshot`을 `as_of` 기준 RANGE 파티션 테이블로 바꾼다.** 파티션은 Asia/Seoul 날짜 하나당 하나이고 이름은 `price_snapshot_pYYYYMMDD`, 경계는 한국 시간 자정이다. 핵심 컬럼(`event_id`, `symbol`, `as_of`, `price`)은 그대로 두고 응답 원문 `raw`(jsonb, 비어 있을 수 있음)를 추가한다.
2. **멱등성 키는 `(event_id, as_of)`.** Postgres는 파티션 테이블의 유니크 제약에 파티션 키가 들어가야 한다고 요구하므로 `event_id` 단독 유니크를 유지할 수 없다. 같은 이벤트는 항상 같은 `as_of`로 오므로 `ON CONFLICT (event_id, as_of) DO NOTHING`이 기존 `eventId` 멱등 처리와 같은 결과를 낸다. 감수하는 점: 같은 `eventId`에 다른 `as_of`가 오면 두 번 저장된다(발행자가 이벤트 ID를 재사용하지 않는다는 전제).
3. **파티션은 저장 직전에 앱이 만든다.** 스케줄러나 기본 파티션 없이, 해당 날짜 파티션이 없으면 만든다(결정: 오케스트레이션 질문 답변). `CREATE TABLE ... PARTITION OF`는 부모에 ACCESS EXCLUSIVE 잠금을 걸어 삽입·조회를 막으므로, 별도 테이블을 만든 뒤 `ATTACH PARTITION`한다(부모에는 SHARE UPDATE EXCLUSIVE만 걸림). 동시에 같은 날짜를 만들려는 경우는 advisory 잠금과 존재 확인으로 한 번만 만든다. 한 번 확인한 날짜는 메모리에 기억한다.
4. **원문은 trim 외에 가공하지 않고 jsonb로 저장한다.** 핵심 컬럼은 이벤트가 담은 값(수집기가 원문에서 파싱한 파생값)이다. jsonb는 키 순서와 토큰 사이 공백을 정규화하므로 바이트 단위 원문은 아니며, 값 안의 공백과 모르는 필드는 보존된다. JSON이 아닌 응답(오류 페이지 등)은 JSON 문자열로 감싸 저장하고 `#>> '{}'`로 원문을 꺼낸다. 이전 형식 이벤트(`raw` 없음)는 `raw`를 NULL로 두고 계속 처리한다.
5. **조회 실패는 `quote_failure`(비파티션)에 저장한다.** `event_id` 단독 유니크로 같은 이벤트를 한 번만 저장하고, `market.snapshot.failed` 계약의 필드 전부(`failureType`, `scheduledFor`, `httpStatus`, `responseCode`, `elapsedMs`, `exceptionType`, 토큰 경과·잔여, 동시 호출 수, tick 성공·실패 건수, `responseRaw`)를 컬럼으로 둔다. 실패 종류에는 CHECK를 두지 않아 새 종류가 생겨도 저장이 막히지 않는다. 컨슈머 처리 실패 메시지를 담는 news의 `failed_event`(ADR-017)와는 다른 용도다.
6. 기존 행이 있는 DB에서는 마이그레이션(V2)이 기존 테이블을 옮기고, 행이 있는 날짜마다 파티션을 만든 뒤 옛 테이블을 지운다. 기존 마이그레이션 V1은 고치지 않았다.

## 미정
- **원문 보존 기간**: 정하지 않았다. 하루치 jsonb 용량과 디스크는 실측 후 정한다. 오래된 날짜 파티션을 떼어 지우는 방식이 가능하도록 날짜별로 나눴다.
- `quote_failure`의 보관 기간도 함께 정한다.

## 후속
- 같은 날짜 파티션을 두 곳에서 동시에 만드는 경우는 advisory 잠금과 단위 테스트로만 확인했고 실제 동시 실행으로는 확인하지 못했다.
- 오래된 날짜 파티션을 지우는 정책을 도입하면 메모리에 기억한 날짜가 낡을 수 있다(재시작 시 해소).
- 바이트 단위 원문이 필요하면 `jsonb`와 별개로 `text` 칸을 둔다(결정 4의 감수 사항).
