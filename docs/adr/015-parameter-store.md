# ADR-015: 이메일 관련 설정·비밀을 AWS Systems Manager Parameter Store에 보관한다

- 상태: **확정** — 지역은 시드니(`ap-southeast-2`)로 쓴다. 읽기 전용 IAM 사용자로 조회 성공을 확인함
- 기록일: 2026-10-20

## 지역 (2026-10-20)
- 이 계정은 시드니(`ap-southeast-2`)만 쓸 수 있다. 서울 등 다른 지역을 쓰려면 계정 업그레이드가 필요하다(콘솔 안내 기준).

## 수신자 (2026-10-20)
- 지금은 수신자가 한 명이라 `recipient`를 파라미터 하나(문자열)로 둔다. 시간당 한도(`max-per-hour`)는 비밀이 아니어서 파라미터로 두지 않고 `application.yml` 기본값을 쓴다.
- 수신자가 여러 명이 되면 DB에 암호화해 저장한다(별도 설계·ADR). 그때 `recipient` 파라미터는 없어진다.

## 맥락
이메일 발송 설정(SMTP 자격증명, 발신·수신 주소, 한도 등)을 지금은 로컬 `.env`(git 제외)에 둔다. 운영(EC2)에서도 같은 값을 써야 하는데, 서버에 `.env` 파일을 복사해 두면 비밀이 디스크에 평문으로 남고 값이 여러 곳에 흩어진다.

## 제안
Parameter Store를 **설정·비밀의 단일 출처**로 삼고, 로컬과 운영이 같은 방식으로 읽는다.

- 경로 규칙: `/stock-reading/<환경>/notifier/<항목>` (예: `/stock-reading/prod/notifier/smtp-password`)
- 유형: 비밀(SMTP 사용자 이름·비밀번호, 수신·발신 주소)은 `SecureString`, 나머지(SMTP 호스트·포트, 한도)는 `String`
- 읽는 방법: **애플리케이션 코드는 바꾸지 않는다.** 시작 전에 로더 스크립트가 `aws ssm get-parameters-by-path --with-decryption`으로 값을 읽어 환경변수(로컬은 git 제외 `.env`)로 만든다. 앱의 인터페이스는 계속 환경변수다(ADR-014).
- 운영(EC2)에서는 **인스턴스 IAM 역할**로 읽는다(저장된 키 없음). 역할 권한은 해당 경로(`parameter/stock-reading/prod/*`)의 읽기와 복호화로 제한한다.

## 확인된 사실 (AWS 문서)
- 표준(Standard) 파라미터는 추가 요금이 없고 기본 유형이다(고급 유형은 과금, 더 높은 처리량을 켜면 API 호출당 과금).
- `GetParametersByPath`의 IAM 검사는 요청한 **경로 기준**이다(상위 경로를 허용하면 하위 전체가 읽힌다).
- `SecureString` 복호화에는 별도로 `kms:Decrypt` 권한이 필요하다. 기본 키(`aws/ssm`)는 **계정의 모든 IAM 주체에게 복호화를 허용**하므로, 접근을 구분하려면 고객 관리형 키를 써야 한다.
- EC2 인스턴스 프로파일은 이 호출의 주체가 될 수 있다.

## 미확인 / 위험
- 고객 관리형 KMS 키 비용(월 요금이 있는 것으로 알고 있으나 확인하지 못함), SecureString의 KMS 호출 요금.
- **Spring Cloud AWS가 Spring Boot 4를 지원하는지 확인하지 못했다**(호환표가 Boot 3.5까지만 확인됨). 그래서 앱에 직접 통합하지 않고 로더 방식을 제안한다.
- **비밀 문제가 한 단계 아래로 옮겨질 뿐이다.** 로컬에서 Parameter Store를 읽으려면 유효한 AWS 자격증명이 필요하다. 장기 키를 새로 만들면 지키고 보관할 비밀이 다시 생기므로, 로컬은 **단기 자격증명**(콘솔 로그인 기반 CLI 로그인, SSO)을 쓰는 방향을 검토한다.- 로컬 실행이 AWS 로그인·네트워크에 의존하게 된다. 완화: 읽은 값을 `.env`에 캐시하고, 오프라인에서는 그 파일로 동작.
- 리전별 서비스이므로 운영 서버(EC2)도 시드니에 두거나, 다른 지역을 쓰려면 계정 업그레이드가 필요하다.

## 대안
- AWS Secrets Manager: 자동 교체 기능이 있으나 비밀당 월 요금이 있다(금액 미확인). SMTP 자격증명 교체가 필요해질 때 재검토.
- 현재 방식 유지(`.env`): 로컬에서는 충분하나 운영에서 비밀이 디스크에 남는 문제가 있다.

## 결정이 필요한 것
KMS 키(기본 vs 고객 관리형). 도입 시점은 지금, 지역은 시드니, 로컬 자격증명은 전용 IAM 사용자로 정했다.
