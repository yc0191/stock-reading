# ADR-011: 1차 알림 채널은 이메일(메일 서비스의 발송 전용 계정 SMTP)로 한다

- 상태: **확정**
- 기록일: 2026-10-20 (바뀐 경위: [history/011-notification-channel.md](history/011-notification-channel.md))

## 맥락
기준 3(대안이 둘 이상): 브리핑을 받아 볼 채널이 필요하고, 서비스는 외부 접속을 받지 않는다(ADR-007). 받는 쪽은 발신 주소의 도메인과 서명(DKIM)·발신 서버(SPF) 도메인이 맞아야(DMARC) 경고 없이 메일을 보여 준다.

## 결정
이메일을 무료 메일 서비스의 발송 전용 계정으로, 그 서비스의 SMTP와 앱 비밀번호를 써서 보낸다. 발신 주소도 그 계정 주소로 한다. 발송기는 채널을 바꾸거나 더할 수 있게 `MailSenderPort` 뒤에 두며, SMTP 서버는 설정값(`spring.mail.*`)만 바꿔 옮길 수 있다.

## 이유
1. 아웃바운드 전용 방침과 맞는다.
2. 길이 제한이 없어 원인 설명과 근거 링크를 충분히 담는다.
3. 발신 주소와 서명·발신 서버의 도메인이 같아 받는 쪽 인증(SPF·DKIM·DMARC)을 통과하고 "보낸 사람을 확인할 수 없음" 경고가 붙지 않는다.
4. 도메인 비용과 DNS 관리가 없다.

## 다른 후보
- AWS SES + 무료 메일 주소: 서명 도메인이 발신 주소와 달라 DMARC가 실패하고 모든 메일에 경고가 붙는다.
- AWS SES + 자체 도메인: 인증은 통과하지만 도메인 비용과 DNS 관리가 든다. 받는 사람이 늘어 메일 서비스의 발송 한도에 가까워지면 옮긴다. 무료 도메인은 회수와 낮은 평판 위험이 있어 쓰지 않는다.
- 메신저: 본인에게만 보낼 수 있고 토큰 갱신과 글자 수 제한이 있어, 즉시성이 필요해지면 2차 채널로 본다.

## 감수하는 점
- 앱 비밀번호가 서버에 있다. 유출되면 그 계정의 메일을 읽고 보낼 수 있으므로 개인 계정이 아닌 발송 전용 계정만 쓴다.
- 무료 계정의 하루 발송 한도 안에서만 보낼 수 있다(한도 값은 미확인).
- 메일 원본의 첫 `Received` 줄에 발송 서버의 공인 IP가 남는다.
- 재시작 때 중복 방지는 메모리 기반이라 재시작 직후 같은 메일이 다시 갈 수 있다.
- 같은 종목 급변동의 반복은 발송기가 아니라 시세처리기의 종목별 재발행 간격이 막는다.
