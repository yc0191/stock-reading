# ADR-000: 프로젝트 배경과 시스템 구조 도출

- 상태: **초안**
- 기록일: 2026-10-20

## 배경: 왜 시작했는가
ETF 가격이 움직일 때 시세 앱에서 관련 뉴스를 열어 봐도 **그 뉴스가 실제로 해당 등락과 관련이 있는지 납득이 가지 않았고, 내용도 이해하기 어려웠다.** 가격 변동과 관련된 정보(지수, 환율, 뉴스, 공시)를 **근거와 함께 연결해서** 설명해 주는, 더 정확한 정보가 필요했다.

## 함께 가진 기술 목표
- Kafka와 Redis를 활용한 MSA 구조 설계와 운영 경험
- 서비스 사이의 병목과 네트워킹을 직접 제어해 보는 경험

## 해결하려는 문제
특정 종목의 가격 변동이 있을 때 그 **원인 후보를 근거와 함께** 정리해서 받아 본다.

## 문제에서 도출된 필요 기능과 구조
| 필요 | 그래서 필요한 구성 |
|---|---|
| 가격 변동을 알아야 한다 | 시세 조회 (시세 API) |
| 변동의 원인 근거가 필요하다 | 지수, 환율, 뉴스, 공시 수집 |
| 수집한 정보를 쌓고 과거를 다시 볼 수 있어야 한다 | DB, 이벤트 보관(Kafka) |
| 근거를 모아 원인 설명을 만들어야 한다 | RAG: 저장된 데이터를 검색해 LLM에 넣는 로직 |
| 결과를 받아 볼 수 있어야 한다 | 이메일 (ADR-011) |
| 위 단계들이 서로 다른 속도와 실패 특성을 가진다 | 서비스 분리와 비동기 메시징 |

## 범위
- 대상: 특정 종목
- 1차 목표: 장 마감 후 일 단위 원인 설명, 이후 시간별 브리핑으로 확장

## 제약
- 서버 2대(AWS EC2) 예정
- 시세 API는 호출 한도·약관이 확인되지 않은 부분이 있다.
