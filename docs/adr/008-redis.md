# ADR-008: 인스턴스 사이의 공유 카운터와 캐시는 Redis로 한다

- 상태: **확정** (도입 보류: 지금은 쓰지 않음)
- 기록일: 2026-10-20

## 맥락
기준 3(대안이 둘 이상): 외부 API(뉴스, 시세, LLM)에는 호출 한도가 있고 LLM 호출은 느리고 비용이 든다. 서비스 인스턴스가 여럿이면 이 한도와 캐시를 함께 써야 한다.

## 고려한 대안
Valkey, Memcached, PostgreSQL만 사용

## 결정
인스턴스 사이에서 공유할 카운터와 캐시가 필요해지면 Redis를 쓴다. 용도는 외부 API 호출 예산(일일 한도, 속도 제한)과 LLM 결과 캐시다.

2026-11-12 변경: 서버 한 대·수집기 하나인 지금은 도입하지 않는다. 메모리 안 호출 상한이 정확하고, 컨테이너를 늘리지 않는다. 여러 인스턴스가 될 때 도입한다.

## 이유
1. 두 용도는 실제 부하 지점(외부 API 한도, 급변동 때 LLM 호출 폭주)과 바로 이어진다.
2. 공유 카운터와 TTL 캐시는 Redis의 기본 용도다.

## 쓰지 않는 용도
뉴스 중복 제거, 이벤트 멱등 처리, 알림 중복 방지는 DB 유니크 제약과 트랜잭션이 더 정확하다(Redis와 DB는 한 트랜잭션으로 묶이지 않는다).

## 도입 준비
시세 호출 상한은 `CallRateLimit` 인터페이스(collector `marketdata`) 뒤에 있어 구현만 바꿔 끼운다.
