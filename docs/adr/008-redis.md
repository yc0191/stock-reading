# ADR-008: 잃어도 되는 공유 캐시와 짧은 잠금은 Redis로 한다

- 상태: **확정** (구현·검증됨: 수집기 최근 검색 보관소)
- 기록일: 2026-10-20

## 맥락
기준 3(대안이 둘 이상): 외부 API(뉴스, 시세, LLM)에는 호출 한도가 있고 같은 검색을 짧은 간격에 되풀이하면 한도를 쓴다. 재시작해도 남고, 수집기가 여럿이 되어도 함께 쓰는 캐시와 "지금 누가 하고 있다" 표시가 필요하다.

## 고려한 대안
Valkey, Memcached, PostgreSQL만 사용, 서비스 메모리

## 결정
잃어도 되는 공유 상태는 Redis에 둔다. 지금 쓰는 곳은 수집기의 최근 검색 결과와 검색 중 표시(`RecentSearchesPort`의 Redis 구현)다.

- **두는 것:** 만료가 있는 캐시, 짧은 잠금, 외부 API 호출 예산 카운터처럼 잃어도 다시 만들거나 그냥 다시 하면 되는 것만 둔다.
- **두지 않는 것:** 원본 자료, 이벤트 멱등 장부, 판정 결과, 발송 기록, 비밀값. 이것들은 PostgreSQL에 둔다(유니크 제약과 트랜잭션이 정확하고, Redis와 DB는 한 트랜잭션으로 묶이지 않는다).
- **키:** `<서비스>:<용도>:<식별자>`. 검색어·종목처럼 관심 대상이 드러나는 식별자는 해시로 쓴다. 모든 키에 만료를 건다.
- **없어도 동작:** Redis가 닿지 않으면 경고 로그를 남기고 캐시가 비어 있는 것처럼 동작한다(예: 다시 쓰지 않고 검색).
- **운영:** 서비스 서버 Compose에 둔다. 디스크에 저장하지 않고, 메모리 상한을 넘으면 오래 안 쓴 키부터 지운다. 설정은 Compose의 `command`에만 두고 실행 중에 바꾸지 않는다(`CONFIG SET` 금지). 포트는 서버 밖으로 열지 않는다. 값은 `infra/deploy/compose/services.yml`의 `redis`가 원본이다.

## 이유
1. 만료가 있는 캐시와 만료가 있는 잠금(`SET NX PX`)은 Redis의 기본 용도라, 표시를 잡은 쪽이 죽어도 저절로 풀린다.
2. 서비스 메모리는 재시작하면 비고 인스턴스끼리 나눠 쓰지 못한다. PostgreSQL로 하면 만료·잠금을 직접 만들고 지워야 하며, 잃어도 되는 자료가 백업과 장부에 섞인다.

## 감수하는 점
컨테이너가 하나 늘고, 서비스 서버 메모리를 조금 더 쓴다. Redis가 죽으면 그동안은 다시 쓰기 없이 검색해 호출 수가 늘지만, 하루 호출 상한은 그대로 지켜진다.
