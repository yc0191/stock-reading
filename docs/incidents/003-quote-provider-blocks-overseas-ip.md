# 003. 운영 서버에서 시세 제공자에 연결이 전부 안 됨

- 상태: 조치함 - 운영 장중 2일로 확인 중
- 기록일: 2026-11-16
- 관련: 이슈 #74, PR #73

## 증상

2026-11-16(월) 장 시작 전 첫 호출부터 운영 수집기가 시세 제공자에 연결하지 못했습니다.

- 토큰 발급이 모두 연결 맺기 시간 초과로 실패해, 시세 제공자에서 받는 자료(현재가, 지수, 환율, 해외 일봉)가 전부 빠졌습니다.
- 주말 동안 호출이 없었는데도 첫 연결부터 막혔고, 몇 시간 동안 풀리지 않았습니다.
- 같은 서버의 다른 외부 연결(뉴스 검색, 공시, 코드 저장소)은 정상이었습니다. 데일리 판은 기사·공시만으로 나갔고, 급변동 메일은 나가지 않았습니다.

## 조사

- **연결만 맺어 보기:** 앱키 없이 시세 제공자의 API 포트에 TCP 연결만 맺어 봤습니다. 운영 서버에서는 모두 실패했고, 같은 시각 국내 개발 환경에서는 모두 성공했습니다. 상대 서버 장애가 아니라 운영 서버에서만 막힌 것입니다.
- **서버의 다른 연결:** 같은 운영 서버에서 다른 외부 주소(443번)에는 연결됐습니다. 서버 네트워크 전체의 문제가 아닙니다.
- **시세 제공자 공지:** 고객정보 보호를 위해 해외 IP에서 오픈 API 접속을 막는다는 공지가 있었습니다. 국내 IP는 그대로 쓸 수 있고, 해외 서버·VPN은 제한될 수 있다고 안내합니다.
- **옮길 곳 먼저 확인:** 국내 리전에 임시 서버를 만들어 같은 연결 시험을 했고 모두 성공했습니다. 클라우드 IP라서 막는 것은 아니라는 확인입니다.

## 원인 (확정)

운영 서버가 해외 리전에 있었고, 시세 제공자가 해외 IP의 접속을 막았습니다.

## 고친 것과 고르지 않은 대안

| 선택지 | 판단 |
|---|---|
| **서버 2대만 국내 리전으로 옮김 (고름)** | 시세 제공자를 부르는 서버만 허용 지역에 있으면 됩니다. 이미지·설정·백업 저장소는 그대로 두어 배포 파이프라인을 바꾸지 않았습니다 |
| 모든 자원을 국내 리전으로 옮김 | 한 지역이라 단순해지지만, 이미지 저장소·설정값·백업 버킷·CI 설정을 함께 바꿔야 해 장애 중에 바꿀 곳이 많습니다. 나중에 다시 봅니다 |
| 국내 중계 서버(프록시)를 거쳐 호출 | 해외 접속을 막은 상대의 의도를 우회하는 것이라 고르지 않았습니다 |
| 호출을 멈추고 기다림 | 일시 제한이 아니라 정책이라 기다려도 풀리지 않습니다 |

옮긴 순서: 기존 서버를 Terraform 상태에서 빼 지워지지 않게 하고 → 새 서버 2대를 만들어 준비 → 기존 서비스를 멈추고 마지막 백업 → 새 데이터 서버에 복원 → 새 서비스 시작. 자세한 절차는 PR #73의 커밋 메시지에 있습니다.

## 시도와 결과

### 조치: 서버를 국내 리전으로 옮김 (PR #73)

- 전환 직후부터 토큰 발급 실패가 없어지고 시세가 다시 쌓였습니다. 그날 시세가 끊긴 시간은 장중의 대부분이었습니다.
- 판정 기준과 결과: 이슈 #74의 "시도 1" 댓글. 판정이 나면 여기에 요약합니다.

## 배운 점

- 외부 API는 접속 지역 조건을 정책으로 바꿀 수 있습니다. 서버 위치를 고를 때 비용과 계정 제약뿐 아니라, 부르는 API의 지역 조건도 확인해야 합니다.
- "연결 맺기 단계에서 실패, 같은 서버의 다른 주소는 정상, 다른 지역에서는 정상"이면 상대의 출발지 차단을 먼저 의심합니다. 앱키 없이 TCP 연결만 맺어 보는 시험이 원인을 가장 빨리 갈랐습니다.
- 서버만 다른 지역에 둘 수 있게 인프라를 나눠 두면, 장애 중에 바꿀 곳이 적습니다.
