# 문제 기록 (Incidents)

운영에서 겪은 문제 가운데 원인을 찾고 고친 과정을 남겨 둘 만한 것을 문제 하나당 문서 하나로 기록합니다. 설계 결정은 [ADR](../adr/README.md)에, 증상의 원본은 GitHub 이슈에 있고, 이 문서는 조사와 판단의 흐름을 남깁니다.

| # | 문제 | 상태 |
|---|---|---|
| [001](001-quote-calls-stall-together.md) | 시세 조회가 한꺼번에 10초씩 멈춤 | 진행 중(시도 1) |

## 기록하는 것

아래 중 하나 이상에 해당하는 문제를 기록합니다.

- 증상만 보고는 원인을 짐작하기 어려워, 가설을 세우고 기록·측정·재현으로 좁혀 간 문제
- 고치는 방법이 여럿이었고, 고른 방법과 버린 방법의 이유를 남겨 둘 가치가 있는 문제
- 이 프로젝트 밖에서도 같은 원리로 다시 만날 수 있는 문제(라이브러리의 기본 동작, 프로토콜, 네트워크, 동시성 등)

단순한 오타, 설정 누락, 바로 원인이 보인 버그는 기록하지 않습니다. 커밋과 이슈로 충분합니다.

## 어떤 문제가 어디까지 가나

```
운영 문제 → 이슈 (전부)
   └ 원인이 추정이라 고쳐도 효과를 재 봐야 아는 것 → 가설 반복 (아래 진행 방식)
        └ 위 "기록하는 것"에 해당 → 이 폴더의 정리본
```

원인이 확실한 버그는 고치고 이슈를 닫으면 끝입니다.

## 진행 방식: 이슈에서 반복하고, 여기에는 정리본을 둔다

문제 하나는 GitHub 이슈 하나에서 "가설 → 조치 → 판정"을 반복하고, 통과하면 끝냅니다. 판정 기준은 **결과를 보기 전에** 정합니다. 결과를 본 뒤 정하면 통과에 맞춰 기준을 고르게 되기 때문입니다.

```
시도 N · 판정 기준 댓글   운영 배포 전에 단다(댓글 시각이 "데이터를 보기 전"의 근거)
        ↓ 배포
시도 N · 결과 댓글        측정일마다 비율과 판정
        ├ 통과 → 이슈 닫기, 이 폴더의 기록을 "해결됨"으로 갱신
        └ 실패 → 무엇을 배제했는지 적고 시도 N+1의 가설로
```

- **판정을 기다리는 이슈**: 판정 기준 댓글을 단 이슈에 `verifying` 라벨을 붙이고, 통과하거나 실패하면 뗍니다.
- **기준선과 측정 기간**: 조치 전 장중 2일을 기준선으로, 배포 뒤 장중 2일을 측정합니다. 두 날 모두 기준을 넘어야 통과입니다.
- **조치가 운영에 있었는지**: 그날 데이터로 확인할 방법을 판정 기준에 함께 적습니다(예: 시간 초과가 새 제한값 근처에서 끊겼는지).
- **판정**: 통과 / 실패 / 판정 보류. 보류는 측정할 수 없었던 날(휴장, 그날 운영에 조치가 없음, 다른 변경과 지표가 섞임)에만 쓰고, 측정 기간에 세지 않습니다.
- **함께 나간 변경**: 판정 기준을 정할 때 같은 시기에 배포될 다른 조치가 지표를 건드리는지 보고, 건드리면 지표에서 떼어 냅니다. 결과 댓글에는 그날 함께 나간 변경을 항상 적습니다.
- **실패한 시도의 조치**: 되돌리지 않고 그 위에 다음 조치를 쌓는 것이 기본입니다. 지표를 나쁘게 한 조치만 되돌립니다. 다음 시도의 기준선은 직전 시도의 결과입니다.
- **공개하는 숫자**: 비율만 씁니다. 건수는 날짜·회차 수와 합치면 개인 투자 정보(종목 수)를 계산할 수 있어 쓰지 않습니다.
- **판정 기준을 바꿀 때**: 결과를 본 뒤 바꾸면 그 시도는 무효로 하고, 바꾼 기준으로 새 시도를 엽니다.

### 판정 기준 댓글

```
### 시도 N · 판정 기준
- 가설: 원인이 무엇이라고 보는가
- 조치: 무엇을 바꿨나 (PR 번호)
- 지표: 무엇을 어떻게 세나 (분자/분모)
- 기준선: 조치 전 값(장중 2일)
- 운영 반영 확인: 그날 조치가 운영에 있었는지 데이터로 보는 방법
- 통과: 지표마다 통과값
- 측정: 배포 뒤 장중 2일 (배포 예정일)
```

### 결과 댓글

```
### 시도 N · 결과 (측정일)
- 지표: 값 (기준선 → 이번)
- 운영 반영 확인: 결과
- 함께 나간 변경: 없음 / 있으면 무엇과 지표에 영향이 있는지
- 판정: 통과 / 실패 / 판정 보류 (이유)
- 실패라면: 이 결과로 배제한 것, 다음 가설
```

## 정리본의 구성

이 폴더의 파일 이름은 `NNN-주제.md`입니다. 진행 중에도 먼저 써 둘 수 있고, 끝나면 시도 전체를 담아 갱신합니다. 실패한 시도도 빼지 않습니다.

1. 상태: 진행 중(시도 N) / 해결됨
2. 증상
3. 조사: 무엇을 보고 무엇을 배제했나
4. 원인: 확정인지 추정인지 밝힘
5. 고친 것과 고르지 않은 대안
6. 시도와 결과: 시도마다 가설, 조치, 판정(이슈 댓글을 근거로)
7. 배운 점
8. 관련: 이슈, PR, 코드·설정 위치

## 작성 원칙

- 숫자는 이슈에 이미 공개한 것만 씁니다. 운영 서버의 위치, 계정·주소, 개인 투자 정보(종목, 종목 수)는 쓰지 않습니다.
- 설정값과 기본값의 원본은 코드와 `application.yml`입니다. 이 문서는 위치만 가리킵니다.
- 확인하지 못한 것은 "추정" 또는 "미확인"으로 표시합니다.
