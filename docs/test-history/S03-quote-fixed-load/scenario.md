# S03 시세 조회 부하(가짜 서버): 사양

종목 n개를 1초마다 한 번씩(초당 n회) 조회할 때 수집기가 **1초 안에 끝내는지, 종목이 늘수록 느려지는지, 호출 상한 장치가 호출을 놓치는지**를 기록합니다. 실제 시세 제공자 대신 로컬 가짜 서버(`FakeBrokerServer`)를 쓰므로 실행 사이에 달라지는 값이 우리 코드와 환경뿐입니다. 제공자 서버의 실제 호출 한도와 지연은 이 시나리오로 알 수 없습니다.

## 사양
- **구성**: 수집기의 시세 조회 부분(`BrokerMarketData`, `BrokerClient`, 호출 상한 장치)과 가짜 서버만 같은 프로세스에서 돌립니다. Kafka와 DB는 거치지 않습니다(전체 흐름은 별도 시나리오 후보).
- **도구**: `QuoteFixedLoadTest`(`QUOTE_LOAD=1`일 때만 실행). 실행 예:
  `QUOTE_LOAD=1 QUOTE_LOAD_OUT=<결과 파일> ./gradlew :services:collector:cleanTest :services:collector:test --tests '*QuoteFixedLoadTest' --no-build-cache`
  `cleanTest`를 빼면 이전 결과가 같다고 보고 시험을 건너뜁니다(환경변수는 그라들 입력이 아님).
- **입력**: 종목 n개(가짜 코드), 가짜 서버는 항상 같은 응답을 60ms 늦게 줍니다. 토큰은 반복마다 새로 발급합니다.
- **한 번의 반복**: 서버와 수집기 객체를 새로 만들고, 1초마다 tick을 만들어 종목을 한꺼번에 조회합니다. tick이 밀리면 다음 tick이 늦게 시작되고(리스너가 하나인 실제 구조), 3초 넘게 밀린 tick은 조회하지 않고 건너뜁니다(실제 규칙).
- **고정**: 가짜 서버 지연 60ms(실서버를 장 마감 후 측정한 평균 47~70ms 근처), 호출 상한은 기본이 종목 수와 같음(`QUOTE_LOAD_CAP`으로 바꿀 수 있음).
- **측정**: 한 번 조회하는 데 걸린 시간(첫 tick은 토큰 발급과 연결 수립이 들어가 따로, 2번째 tick부터의 중앙값·상위 5%·상위 1%·최대), 성공·실패 건수와 실패 종류, 밀려서 건너뛴 tick 수, tick이 예정보다 늦게 시작한 최대 시간, 가짜 서버가 받은 호출 수와 동시에 처리한 최대 요청 수, 앞쪽 20개 tick과 뒤쪽 20개 tick의 중앙값(시간에 따른 변화).
- **합격 기준**: 정하지 않았습니다. 처음에는 숫자를 기록하고, 그 숫자를 본 뒤 기준을 정합니다.
- **기록하지 않는 것**: 시세 값, 종목 코드. 건수와 시간만 적습니다.

## 한계
- 가짜 서버는 지연이 항상 60ms로 고정입니다. 실서버는 지연이 흔들리고 호출 한도가 있어서 결과가 다릅니다.
- 시세 조회 부분만 잽니다. 이벤트 발행, DB 저장, 급변동 감지에 드는 시간과 부담은 포함하지 않습니다.
- 다른 작업이 함께 도는 개발용 기기에서 쟀습니다. 숫자의 절댓값보다 조건 사이의 차이를 봅니다.
