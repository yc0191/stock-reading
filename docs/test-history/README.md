# 테스트 기록

시스템을 실제로 돌려 본 결과를 남깁니다. 나중에 성능을 개선했을 때 "무엇을 바꿔서 무엇이 달라졌는지" 전후를 비교하기 위한 기록입니다. 가설을 증명하는 `docs/hypotheses/`와 달리, 그 시점의 상태를 적습니다.

## 시나리오
| 시나리오 | 입력 | 용도 |
|---|---|---|
| [S01 실제 API](S01-real-api/scenario.md) | 실제 뉴스 검색 API | 실제 환경에서 에러 없이 반복 수집되는지, 그때의 상태를 기록. 외부 영향이 커서 숫자를 직접 비교하지 않음 |
| [S02 고정 입력](S02-fixed-input/scenario.md) | 가짜 검색 서버(항상 같은 응답) | 개선 전후의 처리 시간을 공정하게 비교 |
| [S03 시세 조회 부하](S03-quote-fixed-load/scenario.md) | 가짜 시세 서버(고정 지연) | 종목 n개를 1초마다 조회할 때 수집기가 버티는지, 호출 상한 장치가 호출을 놓치는지 |

| [S04 시세 조회 실제 API](S04-quote-real-api/scenario.md) | 시세 제공자 실제 서버(읽기 전용 조회) | 제공자의 호출 한도가 어느 속도에서 걸리는지, 그 속도를 얼마나 오래 유지할 수 있는지. 외부 영향이 커서 숫자를 직접 비교하지 않음 |

## 기록 규칙
1. 한 번에 바꾸는 변수는 하나입니다. 무엇을 바꿨는지 실행 목록의 "변경" 열에 적습니다.
2. 같은 조건으로 3회 이상 반복합니다. 도중에 환경 문제(예: 기기 절전)로 무효가 된 반복은 결과에서 빼고 사건에 적습니다.
3. 오류와 코드 수정은 해당 문서의 "사건"에 시각, 증상, 원인, 조치로 적습니다. 코드를 고치면 그 실행은 끝내고 새 실행 번호로 처음부터 다시 돌립니다.
4. 기록은 고치지 않고 덧붙입니다. 틀린 내용은 정정을 추가합니다.
5. 검색어, 종목코드, 기사 제목·URL, 키, 접속 정보는 쓰지 않고 개수와 시간만 적습니다. 원본 로그는 저장소에 올리지 않고 로컬에만 둡니다.
