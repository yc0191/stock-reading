## R025: 두 브랜치를 합친 뒤 연동 확인 (2026-10-28)
합친 `BrokerClient`로 토큰 1회, 현재가 1회, 마감 후 조회 2회(시장종합, 일봉)를 호출했습니다. 모두 정상이었고, 토큰은 한 번 발급해 세 호출이 같이 썼습니다.

## 사건
| 시점 | 증상 | 원인 | 조치 |
|---|---|---|---|
| 첫 시도 두 번 | 토큰 발급 거절(HTTP 500) | 로컬 `.env`의 앱키가 37자로 Parameter Store의 36자와 달랐음(시크릿은 같음) | 키를 Parameter Store에서 직접 읽는 시험 도구를 만들고, 거절 뒤에는 표식 파일로 재실행을 막음. 같은 실패를 두 번 보낸 뒤 멈춤 |
| R018 1차 | 27초 만에 클라이언트 예외 | 미확인 | 예외 원인 사슬을 기록하도록 도구 수정 |

## 제공자 답변 (2026-10-28 문의 회신)
- 호출 한도는 **앱 기준 초당 40회(TPS), API별 초당 20회**입니다. 현재가 조회는 한 API이므로 이것만으로는 초당 20회가 상한이고, 같은 앱의 다른 API(일봉, 지수 등)와 합쳐 40회까지입니다.
- 과도하거나 비정상적인 반복 호출은 사이버 공격으로 의심되어 **해당 IP의 접속이 제한될 수 있습니다.** 앱키는 차단되지 않습니다.
- **관측과 맞지 않습니다.** 공식 상한 20보다 낮은 초당 13~15회가 걸렸습니다. 원인은 모릅니다. 호출이 같은 초 안에 몰렸거나, 초당 값 외에 다른 기준(짧은 시간 누적, IP 단위 감시)이 있을 수 있다는 가설뿐입니다.

## 요약과 남은 일
- 5분 통과: 초당 5, 9, 10, 12회. 걸림: 13회(약 51초), 14회(약 20초), 15회(약 22~25초), 20회(약 10초).
- 지속 가능한 한도는 **12회 이상 13회 미만**입니다.
- 호출 상한 기본값을 15에서 5분 통과 속도(12회)보다 낮은 **10으로 낮췄습니다**(2026-10-28, ADR-012).
- 확인하지 않은 것: 11회, 하루 종일 유지, 장중 응답.
