# 설계 문서 규칙

ADR, README, `docs/local-development.md` 같은 설계 문서를 쓰거나 고칠 때 읽습니다. 형식과 상태 정의는 `docs/adr/README.md`가 기준입니다.

## ADR을 쓰는 때

- 구조, 기술 선택, 안전 규칙처럼 나중에 "왜 이렇게 했는지" 물을 결정을 바꾸거나 새로 정했을 때 씁니다.
- 번호는 마지막 번호의 다음 값을 쓰고, 파일명은 `NNN-주제.md`입니다.
- 구성은 기존 ADR을 따릅니다. 상태, 기록일, 맥락, 고려한 대안, 결정, 이유를 기본으로 하고, 검증·감수하는 점·후속 같은 섹션은 필요할 때 추가합니다.
- 결정이 바뀌면 지우지 않고 상태를 `대체됨(Superseded by ADR-0xx)`으로 바꾸고 새 ADR을 추가합니다.

## 상태

- **확정**: 합의했고, 구현이 있으면 테스트로 검증된 것. 구현·검증된 경우에만 `(구현·검증됨)`을 붙입니다.
- **초안**: 방향은 정했으나 세부를 구현하며 더 검토할 것.
- 코드에 없는 기능을 "구현됨"으로 쓰지 않습니다.

## 함께 맞출 곳

- ADR을 추가하거나 상태를 바꾸면 `docs/adr/README.md`의 표(번호, 주제, 상태)를 같이 고칩니다.
- 실행 명령, 설정 키, 테스트 명령이 바뀌면 `docs/local-development.md`를 같이 고칩니다. 테스트 개수 표도 포함입니다.
- 아키텍처, 기술 스택, 서비스 구성이 바뀌면 README의 흐름도, 기술 스택, 로드맵 체크박스를 같이 고칩니다.
- 문서를 옮기거나 지우면 링크가 끊기지 않는지 확인합니다.

## 쓰지 않는 것

- 이메일 주소, 보유 종목·수량·금액, 계좌, 계정 식별자, 키·토큰은 쓰지 않습니다. 유형으로만 설명합니다.
- 외부 사실은 근거를 남기고, 확인하지 못한 것은 "미확인"으로 표시합니다.
