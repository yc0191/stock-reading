# 근거 자료 연결 규칙

새로 수집하는 자료를 브리핑 근거(LLM 입력)로 붙일 때 읽습니다. 자료마다 요청·응답 한 쌍으로 두는 이유는 ADR-010의 "v1 확장"에 있습니다. 아래 항목을 차례로 정하고, 하나라도 빠지면 그 자료가 오류 없이 빠지거나 다른 변동에 잘못 붙습니다.

## 1. 자료 성격 정하기

- **사건형**(뉴스, 공시처럼 일어난 일을 알리는 자료): 발행·접수 시각이 변동 시각 T 기준 범위 안인 것만 씁니다.
- **상태형**(지수, 환율, 시장종합, 일봉, 해외 등락률처럼 그때의 값): 받은 시각이 T 이전인 것 중 최신 값을 쓰고, 기준 기간보다 오래되면 없음으로 표시합니다. LLM 입력에서는 배경 자료로 묶고 받은 시각과 변동보다 얼마나 전 값인지를 붙입니다.
- 어느 변동에 붙는지 정합니다: 시장 전체 자료는 모든 변동에, 종목 자료는 그 종목에만, 미국 자료는 그 ETF에 담긴 미국 종목에만 붙입니다.

## 2. 요청·응답 한 쌍

자료를 가진 서비스가 응답하는 요청·응답 이벤트를 둡니다. 기존 응답에 얹지 않습니다(ADR-010).

1. 스키마와 v1 샘플: `contracts/events/<토픽>.v1.schema.json`, `contracts/events/samples/v1/`
2. 토픽 선언: 쓰는 모든 서비스의 `Topics`와 브리핑 `main.py`의 `TOPIC_PARTITIONS`. 파티션 수를 같게 둡니다.
3. 복제 이벤트 모델: 응답하는 서비스의 이벤트 모델과 브리핑의 파싱 코드
4. 계약 테스트: 응답하는 서비스의 `*ContractTest`, 브리핑 `tests/test_contracts.py`, 토픽 선언 테스트(`TopicsConfigTest`, `tests/test_topics.py`)
5. 다시 요청하는 규칙(`seq`, 제한 시간, 총 시도 횟수)은 기존 쌍과 같게 하고, 끝내 응답이 없을 때의 실패 사유를 `jobs.py`의 `FailureReason`과 실패 테이블 제약에 더합니다.

상세 절차는 `.claude/rules/event-contract.md`입니다.

## 3. 시간 범위와 상한

- 범위와 상한은 `services/briefing/src/briefing/config.py`의 `CoreSettings`에 설정값으로 둡니다. 코드에 숫자를 박지 않습니다.
- 응답하는 서비스에는 같은 뜻의 안전 상한을 `application.yml`에 둡니다. 요청이 더 크면 안전 상한까지만 줍니다.
- 상한을 넘어 잘렸으면 응답에 잘림을 표시하고, LLM 입력에도 상태(있음, 없음, 잘림, 너무 큼, 해당 없음)를 붙입니다.
- 브리핑은 받은 자료의 시각을 다시 검사해 범위 밖이면 버리고 경고 로그를 남깁니다.

## 4. 근거 번호와 LLM 입력

- 자료마다 근거 번호 형식을 정합니다. 원래 식별자가 있으면 그대로 쓰고(기사 번호, 공시 접수번호), 없으면 코드가 접두어와 순번을 붙입니다(`report.py`의 `*_REF_PREFIX`).
- 번호를 `evidence_catalog`에 넣어야 LLM이 인용할 수 있고, 목록 밖 번호는 `parse_output`이 거부합니다.
- `build_llm_input`에 넣을 항목(제목, 시각, 변동보다 얼마나 전인지, 원문 여부)을 정하고, 자료를 읽는 법이 필요하면 `SYSTEM_PROMPT`에 적습니다.
- `briefing.generated` 근거의 `kind`에 쓸 자료 종류 값을 정합니다. 출처에는 제공자 이름 대신 중립 표현을 씁니다.
- 변동마다 남기는 수집 내역 로그(`jobs.py`의 `_log_collection`)에 건수·제외·잘림을 더합니다. 종목코드와 티커는 로그에 쓰지 않습니다.

## 5. 테스트 3종

- 단위: 시간 범위 경계(같은 시각 포함, 직후 제외), 기준 기간 초과, 상한 잘림, 크기 초과
- 가상: 가짜 응답으로 변동 한 건을 처음부터 리포트까지 돌리는 시나리오(`tests/test_scenarios.py`), 응답이 끝내 없을 때의 실패 기록, 목록 밖 번호 거부
- 실제: DB에서 읽는 조회는 `*IntegrationTest`로 빈 테스트 DB에서 확인합니다. 실제 외부 API는 수동으로 최소 횟수만 부릅니다.
