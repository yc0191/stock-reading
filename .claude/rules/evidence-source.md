# 근거 자료 연결 규칙

새로 수집하는 자료를 브리핑 근거(LLM 입력)로 붙일 때 읽습니다. 근거는 자료를 가진 서비스의 내부 조회 API로 묻습니다(조회는 내부 HTTP, 알림은 Kafka, ADR-006·ADR-010의 "근거 조회 규칙"). 아래 항목을 차례로 정하고, 하나라도 빠지면 그 자료가 오류 없이 빠지거나 다른 변동에 잘못 붙습니다.

## 1. 자료 성격 정하기

- **사건형**(뉴스, 공시처럼 일어난 일을 알리는 자료): 발행·접수 시각이 변동 시각 T 기준 범위 안인 것만 씁니다.
- **상태형**(지수, 환율, 시장종합, 일봉, 해외 등락률처럼 그때의 값): 받은 시각이 T 이전인 것 중 최신 값을 쓰고, 기준 기간보다 오래되면 없음으로 표시합니다. LLM 입력에서는 배경 자료로 묶고 받은 시각과 변동보다 얼마나 전 값인지를 붙입니다.
- 어느 변동에 붙는지 정합니다: 시장 전체 자료는 모든 변동에, 종목 자료는 그 종목에만, 미국 자료는 그 ETF에 담긴 미국 종목에만 붙입니다.

## 2. 내부 조회 API

자료를 가진 서비스에 조회 하나를 더합니다. 기존 조회의 응답에 얹지 않고 새 조회로 더합니다(ADR-010).

1. 계약: 요청·응답 본문 모양을 `contracts/events/`의 스키마와 v1 샘플로 둡니다. 기존 조회는 옛 요청·응답 이벤트 스키마의 `payload`를 그대로 계약으로 씁니다.
2. 조회하는 서비스: 계산은 조회 클래스(`*Query`, 요청은 `*Request` 레코드)에 두고 컨트롤러(`*QueryController`)는 그 클래스만 부릅니다. 경로는 `/internal/<서비스>/<자료>`이고 서버 밖으로 열지 않습니다(ADR-007). 입력 오류만 400, 서버 쪽 실패는 500입니다.
3. 브리핑: `queries.py`의 `QueryKind`에 종류를 더하고 `http_queries.py`의 `HttpQueries`로 부릅니다. 다시 부르는 규칙은 `config.py`의 `QuerySettings`를 그대로 씁니다(새 규칙을 따로 만들지 않음). 끝내 실패했을 때의 사유를 `ports.py`의 `FailureReason`과 작업 기록 제약에 더합니다.
4. 계약 테스트: 조회하는 서비스의 컨트롤러·조회 테스트와 실제 웹 서버 테스트, 브리핑 `tests/test_contracts.py`·`tests/test_http_queries.py`
5. 조회해도 되는 때가 따로 있으면(예: 기사는 뉴스처리기의 저장 끝 `news.stored` 뒤) 그 알림을 받은 뒤에 부릅니다. 알림 이벤트를 새로 만들면 `.claude/rules/event-contract.md`를 따릅니다.

## 3. 시간 범위와 상한

- 범위와 상한은 `services/briefing/src/briefing/config.py`의 `CoreSettings`에 설정값으로 둡니다. 코드에 숫자를 박지 않습니다.
- 응답하는 서비스에는 같은 뜻의 안전 상한을 `application.yml`에 둡니다. 요청이 더 크면 안전 상한까지만 줍니다.
- 상한을 넘어 잘렸으면 응답에 잘림을 표시하고, LLM 입력에도 상태(있음, 없음, 잘림, 너무 큼, 해당 없음)를 붙입니다.
- 브리핑은 받은 자료의 시각을 다시 검사해 범위 밖이면 버리고 경고 로그를 남깁니다.

## 4. 근거 번호와 LLM 입력

- 자료마다 근거 번호 형식을 정합니다. 원래 식별자가 있으면 그대로 쓰고(기사 번호, 공시 접수번호), 없으면 코드가 접두어와 순번을 붙입니다(`report.py`의 `*_REF_PREFIX`).
- 번호를 `evidence_catalog`에 넣어야 LLM이 인용할 수 있고, 목록 밖 번호는 `parse_output`이 거부합니다.
- `build_llm_input`에 넣을 항목(제목, 시각, 변동보다 얼마나 전인지, 원문 여부)을 정하고, 자료를 읽는 법이 필요하면 `SYSTEM_PROMPT`에 적습니다.
- `briefing.generated` 근거의 `kind`에 쓸 자료 종류 값을 정합니다. 출처에는 제공자 이름 대신 중립 표현을 씁니다.
- 변동마다 남기는 수집 내역 로그(`jobs.py`의 `_log_collection`)에 건수·제외·잘림을 더합니다. 종목코드와 티커는 로그에 쓰지 않습니다.

## 5. 테스트 3종

- 단위: 시간 범위 경계(같은 시각 포함, 직후 제외), 기준 기간 초과, 상한 잘림, 크기 초과
- 가상: 가짜 조회 결과로 변동 한 건을 처음부터 리포트까지 돌리는 시나리오(`tests/test_scenarios.py`), 가짜 조회 서버로 도는 리허설(`tests/test_rehearsal_direct_calls.py`), 조회가 끝내 실패할 때의 기록, 목록 밖 번호 거부
- 실제: DB에서 읽는 조회는 `*IntegrationTest`로 빈 테스트 DB에서 확인합니다. 실제 외부 API는 수동으로 최소 횟수만 부릅니다.
